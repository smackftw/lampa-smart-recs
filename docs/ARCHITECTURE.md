# Архитектура

## Поток данных

```text
«Нравится / Не нравится» + временное настроение
                         ↓
        общий профиль + веса по типам контента
                         ↓
       текущие фильтры → отбор и discovery TMDB
                         ↓
Lampa TMDB client → кандидаты → scoring → diversity
                                      ↓
                    cache → главная / раздел «Рекомендации»
```

Плагин намеренно не создаёт профиль на удалённом сервере. В своём хранилище он держит бинарные оценки, временное настроение, текущие фильтры и кэш выдачи. Закладки, «Позже», история и другие списки Lampa не читаются. В запросах TMDB виден отдельный ID оценённой карточки, но не передаётся полный профиль.

## Сигналы

Постоянные сигналы — только «Нравится» и «Не нравится». Временные сигналы создаются во время выбора по трейлерам и действуют 6 часов. Для каждого сигнала рассчитывается тип контента: фильм, сериал, аниме или мультфильм. При недостатке сигналов конкретного типа scoring плавно возвращается к общему профилю.

Фильтры не становятся сигналами вкуса. Они ограничивают текущий пул по типу, желаемым и исключённым жанрам и рейтингу.

Вес жанров и языка нормализуется отдельно. Один отрицательный фильм поэтому не способен бесконечно увеличивать штраф. Рекомендации конкретного любимого фильма остаются сильнее общей популярности.

## Производительность Android TV

- Код написан в ES5-совместимом стиле без модулей и runtime-библиотек.
- Сеть ограничена тремя параллельными запросами.
- Используется один общий in-flight запрос для главной и отдельного экрана.
- В хранилище попадают только урезанные TMDB-карточки.
- Результат кэшируется и инвалидируется при изменении оценок или настроения.
- Один iframe-плеер используется для всей трейлерной сессии; ролики меняются через локальный `trailer-player.html`.

## Расширение алгоритма

Чистые функции профиля и scoring находятся в начале `smart-recs.js` и тестируются без Lampa. Позже можно добавить веса ключевых слов, актёров и режиссёров. Для этого потребуется получать полные карточки только для ограниченного числа сильных сигналов, иначе возрастёт число запросов и размер кэша.

## Защищённые функции

`window.LampaSmartRecs.registerProtectedFeature()` регистрирует дополнительную функцию, а `runProtectedFeature()` запрашивает код доступа и обменивает его на короткоживущий токен. AI-провайдер и его секретный ключ должны находиться за шлюзом. GitHub Pages обслуживает только публичный клиентский код.
