# Roadmap MVP после 0.5.2

Этот файл фиксирует согласованные продуктовые решения и следующий порядок работ. Пользовательский README ими не перегружается.

## Что уже считаем фундаментом

- Постоянный вкус строится только по явным «Нравится / Не нравится».
- Прогресс Lampa не становится лайком: он нужен только для скрытия просмотренного; сериал скрывается после двух завершённых серий.
- Текущее настроение живёт отдельно от вкуса, действует 48 часов и учитывает длительность просмотра трейлера.
- Лайкнутые карточки остаются в ротации, но занимают не более 25% партии.
- Геном TMDB, плавное ослабление старых признаков, разнообразие и контролируемое исследование уже работают.
- Фильтры ограничивают текущую выдачу, но не переписывают профиль вкуса.
- AI-провайдер можно будет подключить через изолированный reranker без замены базового алгоритма.

## Следующие этапы

### 1. Стабилизация 0.5.x

- Проверить реальную Android TV-приставку: фокус, Back, возобновление сессии, смену трейлеров и слабую сеть.
- Закрыть найденные TV-баги без добавления новых сущностей в интерфейс.
- Сохранить один стабильный URL установки и совместимость данных между обновлениями.

### 2. Умная калибровка 0.6

- Первые трейлеры выбирать не только по текущему рейтингу, но и по информативности для профиля.
- Начинать с разнообразных диагностических вариантов и после каждого ответа сужать следующую выборку.
- Автоматически оценивать уверенность профиля: при малом числе сигналов исследовать шире, при устойчивом вкусе становиться точнее.
- Цель — получать узнаваемую персонализацию после 10–20 осмысленных действий без анкеты и ручной настройки весов.

### 3. Качество ранжирования 0.7

- Ввести доверительный рейтинг, чтобы высокая оценка при малом числе голосов не обгоняла надёжные фильмы.
- Ослаблять слишком общие признаки генома и усиливать редкие характерные сочетания.
- Расширить разнообразие за пределы жанров: не ставить подряд одну франшизу, одинаковых ключевых актёров или почти одинаковые сюжеты.
- Сделать долю исследования адаптивной по недавним лайкам и пропускам, сохранив гарантированный минимум новых вариантов.
- Проверять качество локально по доле лайков, переходов к просмотру, быстрых пропусков, повторам и разнообразию — без внешней телеметрии.

### 4. Полировка 0.8 и выпуск 1.0

- Довести состояния «нет трейлера», медленной сети, пустой выдачи и последнего успешного кэша.
- Ограничить и обслуживать локальные кэши, проверить миграции и работу на слабой приставке.
- Расширить автотесты на навигацию пультом, ошибки сети и обновление старых данных.
- Зафиксировать MVP после успешного теста на веб-Lampa и Android TV.

## Не входит в текущий MVP

- Синхронизация между устройствами — вернёмся к ней при появлении подходящего CUB-механизма или отдельного безопасного решения.
- AI — только архитектурный задел; базовый рекомендатор обязан хорошо работать самостоятельно.
- Текстовые причины «почему рекомендовано» — не добавляем, чтобы не перегружать карточки.
- Совместная фильтрация по другим пользователям — для неё нужны сервер, аудитория и отдельное согласие на данные.

Главный принцип: не обещать буквально только идеальные фильмы, а постоянно увеличивать точность, сохраняя небольшую контролируемую долю приятных открытий.
