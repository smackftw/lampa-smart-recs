# Безопасность

## Что защищено сейчас

Базовый рекомендатор локальный. Он не имеет учётных данных и не отправляет историю на собственный сервер. Сетевые запросы каталога проходят через внутренний API Lampa, который уже используется самим приложением. Запрос рекомендации содержит TMDB ID одной опорной карточки; полный профиль, CUB-токен и список истории не отправляются.

## Почему нельзя положить пароль в плагин

Любой JavaScript на GitHub и GitHub Pages публичен. Проверка вида `if (password === "...")` скрывает кнопку, но не защищает функцию: пароль можно прочитать, а проверку — удалить. Аналогично нельзя помещать в файл ключ OpenAI/Anthropic/TMDB или постоянный bearer-токен.

## Контракт будущего шлюза

1. Плагин запрашивает код через `Lampa.Input` с `nosave: true`.
2. `POST /v1/session` получает `feature`, `access_code`, имя клиента и версию.
3. Шлюз сравнивает хэш кода с серверным секретом, применяет rate limit и возвращает ограниченный токен на 1–60 минут.
4. Токен остаётся только в памяти WebView.
5. Запросы функции идут с `Authorization: Bearer <token>`; ключ AI-провайдера добавляет шлюз.
6. Шлюз проверяет feature scope, срок, размер запроса и лимит расходов.

Шлюз должен использовать HTTPS, CORS allowlist, журналирование без содержимого истории и отзыв токенов. GitHub хранит его исходный код, но production-секреты задаются только в secret storage хостинга.

## Данные для AI

Перед отправкой нужна отдельная явная настройка. По умолчанию следует передавать агрегированный профиль и ограниченный список названий, а не полную историю, CUB-токен или сведения об устройстве.

О проблемах безопасности сообщайте приватно владельцу репозитория, не публикуя ключи и персональные данные в issue.
